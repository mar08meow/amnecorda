把生活里的小麻烦，做成自己的工具

从 AppPantry 到 HyperOS 动态模糊修复，再到这个站点：我为什么总在做一些很小、但每天都会用到的工具。

文 / AmneCorda Hangzhou

我 GitHub 上的项目，大多不是那种能写进简历首页的东西。它们解决的问题很小：装一个软件、修一张背景、写一篇文章。但它们有一个共同点——我自己每天都会用。

一个判断：工具的价值，取决于它被使用的频率

我们很容易被「更大的项目」吸引：更多功能、更多用户、更完整的技术栈。但真正留在日常里的，往往是那些只解决一个具体问题的小东西。它们不需要解释自己为什么存在，因为你每天都会打开它。

我对个人项目的要求一直很简单：如果我自己不会用，就不做；如果做完之后还要花很多时间维护，就重新想。

AppPantry：把「装软件」这件事收回来

AppPantry 是一个本地优先的 Windows 应用下载、安装与管理工具。它面向刚接触 Windows 的人：不用在搜索结果里翻找，打开清单，找到常用软件，点一下安装。

清单里现在有 154 款应用，其中 28 个是开源项目；也补了 26 款国内常用软件。安装通过 winget 完成，但选择权留在本地：搜索、分类、收藏、最近安装、卸载、残留清理，以及图片和 PDF 转换，都在自己的电脑上完成。

做这个项目的过程，让我反复确认一件事：本地优先不只是技术选择，也是产品态度。 它意味着用户不需要先相信一个陌生的服务器，才能使用自己的电脑。

HyperOS 动态模糊修复：不要修那张图，去把它拿掉

小米平板的工作台模式有一个很具体的问题：把壁纸换成第三方动态壁纸后，打开应用列表，背景会变成系统默认壁纸的静态模糊图。它既不是当前壁纸，也不会动。

一开始我以为是窗口模糊没有生效。读代码后发现，应用列表背景其实有两条路径同时工作：

allAppBackground.setAlpha(1.0f);
WindowBlurUtils.setBlur(viewRootImpl, 0.4f, null);

一条路径铺上一张不透明的静态模糊图，另一条路径开启窗口级实时模糊。静态图把实时模糊完全盖住了。

所以修复不是去修那张图，而是 hook AllAppsBackground#showBlurEffect，在它完成原有逻辑后把 View 背景清成透明，让窗口自己的实时模糊露出来。

这个模块很小，只对使用工作台模式的小米平板有效。但它让我记住：遇到问题，先确认自己看到的是不是真正的那一层。

AMNE CORDA：把「表达」也当成一个工程问题

这个站点是手写 HTML 与 CSS，没有框架。它不只是文章列表，也是一套可以长期维护的小系统：Cloudflare Pages 负责部署，Access 保护后台，GitHub App 负责提交，后台可以发布文章、调整主题、字体和字重；夜间模式跟随系统，RSS 与站内搜索也都在。

我写得很慢。很多文章在笔记里放了两三周，确认自己真的想清楚了，才搬上来。站点本身也一样：先让它每天可用，再一点点补上需要的功能。

共同的原则

如果把这几个项目放在一起看，它们共享几条很简单、但不总是容易做到的原则：

  • 本地优先：能留在设备上的，不要先送到云端。
  • 少依赖：能用系统能力解决的，不引入一整套框架。
  • 自己先用：如果我自己不会每天打开它，就不值得做。
  • 把决定写下来：代码会变，但当时的判断应该留下痕迹。
  • 允许它小：不是每个项目都要成为平台。

最后

我越来越觉得，个人项目最珍贵的部分不是规模，而是它和你的生活之间有没有真实的连接。一个能让你少翻几次搜索结果、少看一次错误的背景、少花十分钟装软件的工具，就值得被做出来。

如果你也在做类似的事情，或者只是想聊聊某个具体的问题，欢迎来 GitHub 或写信。
